## الفكرة باختصار

معظم "محررات الكود" على الموبايل إما أنها مجرد ملوّن نصوص، أو ترسل كودك لسيرفر بعيد يشغّله ويرجع النتيجة. نوفا اختار الطريق الأصعب والأصدق:

1. **تفتح مشروع** (أو تنشئ واحد جديد: PHP / Node / Python).
2. **تتصفح ملفاتك وتعدّلها** في محرر فيه تلوين لغات وتبويبات.
3. **تضغط Run** فيشتغل الكود داخل بيئة لينكس حقيقية **مضمّنة داخل التطبيق نفسه** (مبنية على حزم Termux).
4. **تشوف الناتج** لحظة بلحظة في لوحة الكونسول، أو تفتح تيرمينال كامل، أو تعاين صفحة ويب شغّلها مشروعك.

كل هذا يحدث على جهازك، حتى بدون إنترنت (بعد أول تثبيت للحزم).

## الفلسفة وراء المشروع

- **الموبايل جهاز تطوير حقيقي، مش مشاهد فقط.** الفكرة أنك تبرمج من أي مكان، لا أن تنتظر جهاز الكمبيوتر.
- **التشغيل الحقيقي قبل الشكل الجميل.** أي ميزة شكلية لا تكسر القاعدة: الكود يجب أن يُنفَّذ فعلًا على الجهاز.
- **طبقات رفيعة وواضحة.** الواجهة (Flutter) لا تعرف تفاصيل النظام، والمحرك (Android/Kotlin) لا يعرف شيئًا عن الشاشات. بينهما عقد واحد مولّد آليًا (Pigeon) — لو غيّرت جهة، الجهة الثانية لا تتأثر.
- **لا نعيد اختراع العجلة.** بيئة التشغيل = حزم Termux الرسمية. المحرر = مكتبة `re_editor`. التيرمينال = `xterm`. نوفا يركّب هذه القطع معًا بدل كتابتها من الصفر.
- **الشفافية عند العطل.** أي عملية طويلة (تثبيت حزمة، تشغيل مهمة) تبثّ تقدّمها لحظة بلحظة، والفشل يظهر بسبب واضح لا شاشة صامتة.

## كيف يعمل؟ (آلية العمل)

الصورة الكاملة في خمسة أسطر:

```
┌──────────────┐   Pigeon (دوال)    ┌──────────────────┐
│  واجهة Flutter │ ───────────────▶ │  محرك Kotlin      │
│  شاشات + حالة  │ ◀─────────────── │  تنفيذ + ملفات    │
└──────────────┘  قناة أحداث واحدة └──────────────────┘
       │                                     │
       │ Riverpod (الحالة)                   │ PREFIX لينكس مضمّن
       ▼                                     ▼ (files/usr/bin/…)
```

### 1. الواجهة (Flutter/Dart)

كل ما تراه: المستكشف الجانبي، المحرر، زر التشغيل، الكونسول، التيرمينال، شاشات Git والرن-تايم والإعدادات. الحالة تُدار بـ **Riverpod** (كل شاشة تشترك في مزوّدات `Provider` بدل تمرير المتغيرات يدويًا).

### 2. الجسر (Pigeon)

الواجهة والمحرك لغتان مختلفتان (Dart وKotlin)، والكلام بينهما يتم عبر ملف واحد:

- `pigeons/ide_api.dart` — **العقد**: كل الدوال المتاحة (ملفات، عمليات، تيرمينال، Git، رن-تايم...).
- يُولَّد منه آليًا: `ide_api.g.dart` (لطرف Dart) و `IdeApi.g.kt` (لطرف Kotlin).

> القاعدة: لا تكتب كود الجسر يدويًا أبدًا — عدّل ملف `pigeons` ثم ولّد من جديد.

### 3. قناة الأحداث (Event Channel)

الدوال تنفع للطلب والرد ("افتح ملف"، "ابدأ عملية")، لكن **الأحداث المستمرة** (سطر جديد في الكونسول، نسبة تقدّم تثبيت) تحتاج بثًا حيًا. لهذا توجد قناة أحداث واحدة باسم `sd.adaa.nova/events`.

نقطة مهمة تعلّمناها بالتجربة: القناة تتحمّل **مستمعًا واحدًا فعليًا**. لذلك كل الاشتراكات تمر عبر **`IdeEventBus`** — مفترق واحد يستقبل البث ويوزّعه على (التيرمينال، العمليات، المعاينة، شاشة الرن-تايم). بدونه كانت الأحداث تضيع وتظهر أعراض مثل "التثبيت يبدأ ثم يتجمد".

### 4. المحرك (Kotlin)

مدراء متخصصون، كل واحد مسؤول عن ملفّه فقط:

| المكوّن | وظيفته |
|---|---|
| `ProjectManager` / `FileApiImpl` | المشاريع والملفات (إنشاء، قراءة، حذف...) |
| `ProcessManager` / `ShellExecutor` | تشغيل الأوامر وجمع المخرجات |
| `TerminalManager` / `PtyNative` | جلسات التيرمينال التفاعلية |
| `GitManager` / `GitApiImpl` | عمليات Git الأساسية |
| `RuntimeManager` / `BootstrapInstaller` | بيئة التشغيل وتثبيت الحزم |
| `WebPreviewApiImpl` / `PortDetector` | كشف المنفذ ومعاينة الويب |
| `IdeService` | خدمة أمامية (Foreground) للعمليات الطويلة |
| `IdeCore` | التهيئة عند الإقلاع + إصلاح ذاتي للبيئة |

### 5. بيئة التشغيل (Linux داخل التطبيق)

عند أول تشغيل، يفكّ التطبيق حزمة `bootstrap` تحت مجلد بياناته (`files/usr/...`) — بايثون وNode وأدوات أساسية جاهزة. المسارات المكتوبة داخل الحزمة (`/data/data/com.termux/files/usr`) تُرقَّع آليًا إلى مسار التطبيق الفعلي.

تثبيت حزمة جديدة (مثل `git`) يتم بوصفة مجرّبة: `apt download` للحزمة وتوابعها، ثم فكّ كل `.deb` مباشرة داخل البيئة، ثم إصلاح روابط البداية (`shebang`). هكذا نتجاوز قيدًا في `dpkg` يمنعه من إنشاء مجلدات خارج مساره الأصلي.

```
nova/

│   ├── main.dart / app.dart       # نقطة الدخول + الغلاف العام
│   └── src/
│       ├── core/
│       │   ├── bridge/           # الجسر: native_bridge + events_bus + المولّد
│       │   ├── models/           # نماذج البيانات (مشروع، مهمة، عملية...)
│       │   └── services/         # خدمات الشاشات (ملفات، عمليات، تيرمينال، Git...)
│       └── features/             # الشاشات: workspace، editor، terminal،
│                                 # process، git، runtime، webpreview، lsp، ai
├── android/app/src/main/kotlin/   # المحرك (Kotlin)
│   └── sd/adaa/nova/
│       ├── filesystem/ project/ process/ terminal/
│       ├── git/ runtime/ webpreview/
│       └── MainActivity · IdeCore · IdeService · IdeEvents · AllApis
├── pigeons/ide_api.dart           # عقد الجسر (المصدر الوحيد للحقيقة)
├── test/                         # اختبارات الوحدة + اختبار شامل داخل التطبيق
├── DECISIONS.md                  # سجل القرارات المعمارية
├── plan.md / task.md             # الخطة وتتبّع المهام
└── README.md                     # هذا الملف
```

### الشاشات الرئيسية

| الشاشة | ما تفعله |
|---|---|
| Workspace | المستكشف الجانبي (قابل للطي) + المحرر + زر التشغيل |
| Editor | تبويبات ملفات، تلوين لغات، حفظ، مؤشر التعديلات |
| Run Console | اختيار مهمة، تشغيل/إيقاف، ناتج حي (قابل للطي ويعود تلقائيًا عند الضغط على Run) |
| Terminal | تيرمينال تفاعلي كامل بلوحة مفاتيح مخصصة |
| Process | قائمة العمليات الجارية وإدارتها |
| Git | حالة المستودع والعمليات الأساسية |
| Runtime | تثبيت/تحديث/حذف بيئات التشغيل مع شريط تقدّم حي ونسبة وسرعة تحميل |
| Web Preview | معاينة صفحات الويب التي يشغّلها مشروعك |
| Settings / AI / LSP | الإعدادات، مساعد ذكي متوافق مع OpenAI، ودعم خوادم اللغات |

## الاعتمادات (Dependencies)

### واجهة Flutter

| الحزمة | لماذا نستخدمها |
|---|---|
| `flutter_riverpod` + `riverpod` | إدارة الحالة في كل التطبيق |
| `re_editor` + `re_highlight` | المحرر وتلوين اللغات (خلف تجريد يسمح بتبديله لاحقًا) |
| `xterm` | التيرمينال التفاعلي |
| `flutter_inappwebview` | معاينة الويب داخل التطبيق |
| `dio` | عميل HTTP لخدمة الذكاء الاصطناعي |
| `flutter_secure_storage` | حفظ مفتاح الـ API بأمان |
| `shared_preferences` | حفظ الإعدادات (الثيم، المهلة، عنوان الـ AI...) |
| `file_picker` / `path_provider` / `path` | استيراد الملفات والمسارات |
| `pigeon` (dev) | توليد كود الجسر بين Dart وKotlin |

### طرف أندرويد

- **Kotlin** + Android SDK، `applicationId = sd.adaa.nova`.
- `targetSdk = 28` — **مقصود وليس إهمالًا**: من 29 فصاعدًا يمنع النظام (SELinux) تنفيذ الملفات داخل مجلد بيانات التطبيق، وهو ما يقتل بيئة التشغيل المضمّنة.
- `useLegacyPackaging = true` لنفس السبب.

## التثبيت والتشغيل

### المتطلبات

- Flutter SDK (مجرّب على `3.47.x`) — يتضمن Dart `3.13.x`.
- Android SDK + محاكي أو جهاز حقيقي مع تفعيل `USB debugging`.
- اتصال إنترنت **لأول تشغيل فقط** (تحميل حزم بيئة التشغيل).

### خطوات التشغيل

```bash
# 1. جلب الاعتمادات
flutter pub get

# 2. (عند تعديل pigeons/ide_api.dart فقط) إعادة توليد الجسر
dart run pigeon --input pigeons/ide_api.dart

# 3. فحص سريع
flutter analyze
flutter test

# 4. التشغيل على الجهاز/المحاكي
flutter run

# 5. نسخة APK للتثبيت
flutter build apk --debug
```

> **ملاحظتان توفّران عليك ساعات:**
>
> - بعد أي `flutter pub get` أعد تطبيق رقعة `proguard` لحزمة `flutter_inappwebview_android` (إزالة سطر `-optimize`) وإلا فشل البناء.
> - ابنِ دائمًا عبر `flutter build apk` لا عبر Gradle مباشرة — بناء Gradle وحده قد ينتج APK قديمًا لا يحمل آخر تعديلات Dart.

### أول إقلاع على الجهاز

1. ثبّت الـ APK وافتح التطبيق.
2. انتظر فكّ حزمة البيئة (مرة واحدة فقط).
3. أنشئ مشروعًا (PHP / Node / Python) وافتح ملفًا واضغط **Run**.

## التشخيص على الجهاز

أثناء التطوير يمكنك إثارة أحداث حقيقية عبر `adb` (التطبيق يجب أن يكون في المقدّمة، وبدون تحديد المكوّن `-n`):

```bash
# تثبيت git عبر مسار التثبيت الحقيقي داخل التطبيق
adb shell am broadcast -a sd.adaa.nova.DEBUG_INSTALL_RUNTIME --es id git

# مراقبة الأحداث
adb logcat -s flutter:I | grep IDE-EVENT

# فحص البيئة يدويًا
adb shell "run-as sd.adaa.nova sh -c 'ls files/usr/bin | head'"
```

## مشاكل شائعة وحلولها

| العرض | السبب غالبًا | الحل |
|---|---|---|
| التثبيت يبدأ ثم يتجمد | حدث `runtimeProgress` لا يصل للشاشة | تأكد أن كل الاشتراكات تمر عبر `IdeEventBus` وحده |
| `Unable to locate package X` بعد تحديث | ملفات `sources.list` فُقدت (إعادة فكّ الحزمة تمسح الإصلاح اليدوي) | الإعداد الآن دائم في `BootstrapInstaller.configureApt` — لا تصلحه يدويًا على الجهاز |
| `Permission denied: ./data/data/com.termux` | `dpkg` يرفض إنشاء مساراته الأصلية | هذا طبيعي — التثبيت يتم بوصفة download + فكّ مباشر، لا `apt install` |
| فشل البناء بعد `pub get` | رقعة proguard ضاعت | أعد تطبيقها على `flutter_inappwebview_android-1.1.3` |
| APK لا يحمل تعديلاتك | بُني عبر Gradle مباشرة | ابنِ بـ `flutter build apk --debug` ثم ثبّت |
| `pm clear` لم يصفّر شيئًا | لا يمسح ملفات التطبيق فعليًا هنا | احذف مجلد البيانات يدويًا أو أعد التثبيت مع المسح |

## الحالة الحالية وخارطة الطريق

**يعمل الآن:** المحرر متعدد التبويبات، المستكشف، التشغيل مع ناتج حي، التيرمينال، العمليات، Git، تثبيت الرن-تايم مع تقدّم حي، معاينة الويب، الإعدادات، مساعد AI، ودعم أولي لـ LSP — وكلها مغطاة باختبارات ناجحة على الجهاز.

**التالي المقترح:** إكمال Git (فروع/دمج)، تحسين المحرر (إكمال تلقائي أفضل)، دعم حزم أكثر في الرن-تايم، وتقليل حجم APK.

## المساهمة

1. اقرأ `DECISIONS.md` قبل أي تغيير معماري — القرارات المكتوبة هناك مُلزمة.
2. أي API جديد بين الواجهة والمحرك يُضاف في `pigeons/ide_api.dart` ثم يُولَّد، لا يُكتب يدويًا.
3. بعد أي تعديل: `flutter analyze` ثم `flutter test` — لا تُسلَّم نسخة مكسورة.
4. ميزة جديدة = اختبار يغطيها إن أمكن.
